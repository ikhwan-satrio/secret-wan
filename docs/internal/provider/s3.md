# `internal/provider/s3.go`

> Source: `internal/provider/s3.go` · Package: `provider`

## Purpose

Implements object storage for the encrypted payload using AWS SDK for Go v2. It
works with Amazon S3 and S3-compatible services such as MinIO, Cloudflare R2, and
Backblaze B2.

## Responsibilities

- Derive a default object key from the project name and `AppConfig.EncFile`.
- Read `SECWAN_S3_*` environment variables for configuration.
- Lazily build an S3 client, optionally with a custom endpoint and path-style
  addressing.
- Write, read, and head the configured object with a timeout.
- Map missing-object responses to `ErrNotFound`.

## Configuration

All configuration comes from the environment, so no bucket coordinates or
credentials are written into the manifest.

| Variable | Required | Meaning |
| :--- | :--- | :--- |
| `SECWAN_S3_BUCKET` | yes | Target bucket |
| `SECWAN_S3_KEY` | no | Explicit object key; defaults to `<project>/<EncFile>` |
| `SECWAN_S3_REGION` | no | AWS region passed to the config loader |
| `SECWAN_S3_ENDPOINT` | no | Custom endpoint for S3-compatible services |
| `SECWAN_S3_PATH_STYLE` | no | `true` enables path-style addressing (MinIO) |

Credentials use the standard AWS SDK chain (environment variables, shared
config/credentials files, IAM roles, SSO, and so on).

## Key type

```go
type S3Provider struct {
    Bucket    string
    Key       string
    Region    string
    Endpoint  string
    PathStyle bool
    Timeout   time.Duration

    client  s3API
    once    sync.Once
    initErr error
}
```

`s3API` is a small interface covering `PutObject`, `GetObject`, and `HeadObject`.
It exists so tests can substitute a fake client without a network connection.

## Methods

| Method | Behavior |
| :--- | :--- |
| `Save` | `PutObject` with the ciphertext as the body |
| `Load` | `GetObject`, read and return the body |
| `Check` | `HeadObject` verifies existence and access |

Errors are wrapped with the object URI (`s3://bucket/key`) to make failures
actionable. A missing object becomes `ErrNotFound`.

## Client initialization

`api()` uses `sync.Once` so the SDK configuration and client are built at most
once per provider instance:

1. Validate that `Bucket` and `Key` are non-empty.
2. Load the default AWS config with a 15-second timeout, adding the region when
   set.
3. Build the S3 client, applying `BaseEndpoint` and `UsePathStyle`.

If a test injects `client` directly, `api()` returns it without touching the SDK.

## Default object key

When `SECWAN_S3_KEY` is empty:

```text
<project>/<AppConfig.EncFile>
```

`AppConfig.EncFile` is the single source of truth for the filename and comes from
the global configuration (default `env.enc`). There is no provider-level
fallback: if both `SECWAN_S3_KEY` and `AppConfig.EncFile` are empty, the key
stays empty and validation fails. A blank project name drops the prefix. This
keeps one object per project in a shared bucket.

## Not-found detection

`isS3NotFound` inspects `smithy.APIError` codes. `NoSuchKey`, `NotFound`, and
`404` are treated as missing. Other API errors, network failures, and credential
problems remain ordinary failures.

## Timeouts

- Data operations (`Save`, `Load`, `Check`) use `Timeout`, defaulting to
  30 seconds.
- AWS configuration loading uses a fixed 15-second timeout.
- Contexts are cancelled with `defer cancel()`.

## Dependencies

- `github.com/aws/aws-sdk-go-v2`, its `config` package, `service/s3`, and
  `github.com/aws/smithy-go`.
- [`internal/config`](../config/config.md) for `AppConfig.EncFile`.

## Edge cases and notes

- A missing bucket variable produces a configuration error, not `ErrNotFound`.
- The provider does not create the bucket.
- `Check` requires `s3:HeadObject` permission in addition to read access.
- Path-style addressing is usually required by MinIO and some other
  S3-compatible services.
- The provider is writable and is not offered by `init`; select it by setting
  `project.provider = "s3"`.
- Large payloads are read fully into memory, matching the existing
  `StorageProvider` interface.
